# 单线程性能优化结果

2026-10-26，Apple Silicon arm64，Homebrew GCC 16.2.0，GSL 2.8。

**精度通过，10 倍性能目标未达到。** 当前 2000 个光子的完整程序提速为
**2.43 倍**，输出逐字节一致。本次交付保留经过回归的保守优化；没有以统计
均值、分位数或个别慢种子的提速替代整个任务的验收标准。

## 保留的实现

- 对测地线密集输出的半径和角度做区间计算，并预计算磁场表每个插值单元
  的场强界。结合速度分布的最大速度和电荷质量比，仅在整个区间都不能
  共振时跳过光深积分。边界不确定时继续使用原算法。
- 无共振的测地线步不准备 Magnus 密集输出的三个端点；其接受步、误差
  估计和最终 Stokes 演化保持原有算术顺序。
- 散射率先检查有效共振通道，再按需查询偏振；一次查询供各组分复用。
- 仅在其他逃逸条件满足时计算共振逃逸判据。

PhotonEvolution::Options::fast_transport=false 关闭区间排除和密集输出
准备优化，可用独立驱动的 --reference 参数检查。原 rates、构造函数
和生产输出格式保持兼容；rates_at 增加按需偏振接口。没有改动物理参数、
随机数顺序、积分容限、绝热切换及逃逸条件。

## 性能计数与未保留的方案

插桩单独编译、单独运行，不用于速度验收；插桩版本输出同样逐字节一致。

| 调用 | 原版 | 优化版 |
| --- | ---: | ---: |
| Basis 精确求值 | 70,581,218 | 24,724,183 |
| 共振边界扫描 | 1,096,613 | 205,030 |
| 共振边界求根 | 24,521 | 23,593 |
| QAGS 求积 | 2,234,806 | 451,176 |
| 光深被积函数求值 | 54,152,175 | 16,695,945 |
| 偏振密集输出查询 | 43,494,057 | 10,088,118 |
| 整段排除的光深调用 | 0 | 891,583 |
| Magnus 步进调用（含区间结束查询） | 1,014,400 | 1,014,400 |

原始边界扫描和 QAGS 被保留用于全部有效或不确定区间，因此没有独立的
近似积分回退计数；上述 451,176 次 QAGS 即这些区间使用的原路径调用。

本次还实现并试验了下列方案，但没有将它们留在默认源码中：

| 试验 | 2000 光子观察 | 决定 |
| --- | --- | --- |
| 测地线步内复用共振边界 | 最大偏振差约 8.46e-4，接近上限；耗时未改善 | 撤出 |
| 光深几何分段四次插值，独立检查点容限 1e-11 | 17 个种子超限，最大偏振差约 8.24e-2，且更慢 | 撤出 |
| 旋转范数等价改写 | 23 个种子超限，最大偏振差约 3.85e-2 | 撤出 |
| 偏振插值多项式预展开 | 种子 460 的 U 差约 5.37e-3 | 撤出 |
| 8/16 点 Gauss–Legendre 配对求积，带相位门槛、细分及 QAGS 回退 | 5 个种子超限，最大偏振差约 7.11e-2，耗时未改善 | 撤出 |
| 精确点值缓存 | 输出一致，但散列与复制成本使当前任务更慢 | 撤出 |

8/16 点 Gauss–Legendre 规则本身不是嵌套规则，试验使用两个独立节点集。
误差来自全链路对传播相位和事件位置的敏感性：改变积分分段或浮点运算
顺序，即使局部差异很小，也可能改变后续高频旋转。不能用局部 1e-11
容限证明最终输出满足 1e-3。

剩余成本集中在有效共振区内的高频偏振积分以及大量 Magnus 步进。本次没有
验证出能在全部逐光子误差约束下继续达到 10 倍的方法，也没有以失败试验
代替可用实现。

## 复现与测试

在项目根目录运行；需现有磁场表 table/bfield_t10.txt、GCC 16 和 GSL。
本次冻结源码、二进制与完整输出位于忽略目录
build/single_thread_optimization/。

    make test-transport
    python3 py/benchmark_transport.py
    python3 py/benchmark_transport.py --first 100000 --count 10000
    python3 py/benchmark_transport.py --production --warmup --repeats 5
    python3 py/profile_transport.py

生产基准在精度不通过或速度比不足 10 时返回非零退出码，并在 JSON 中分别
记录 passed、performance_passed 和 target_met。驱动精度命令仅因
精度失败返回非零，性能结果另行记录。

如果本地冻结目录不存在，可先从原提交重建；脚本会恢复 N=2000，且拒绝
覆盖已有基线：

    python3 py/benchmark_transport.py --baseline-revision c55132ca3562d01d8eaf6cbc4d416a74ea61e173

验证结果：

- make test-transport 通过：随机磁场包络、极点、两半球、整段无共振、
  向内/向外传播、根合并、速度边界、散射事件、禁用密集输出的一致性，
  以及验收脚本的阈值、离群值、非有限值检查。
- 当前 2000 光子及扩展 10000 光子回归均通过，全部数值误差为 0。
- --reference 关闭快速路径后，2000 光子输出与冻结原版一致。
- 编译使用警告选项，无新增编译警告；git diff --check 通过。
- 旧的 py/test_fd11_fig7.py 无法在系统 Python 中运行，原因是缺少
  numpy。它检查绘图后处理，不参与本次 C++ 性能及误差验收。
