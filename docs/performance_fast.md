# 第二轮：快速模式与确定性的并行输运

## 使用

```sh
make fd11_fig7
build/fd11_fig7 --fast --threads 8 --photons 1000000 --seed 110701 \
  --output data/fd11_fast_110701.txt
```

原来的四进程批处理可以改为上述单进程八线程运行。多线程使用相同的物理模型、
相同数量的发射光子，包括吸收的光子；没有丢弃慢光子、减少样本数或更改输出分箱。
线程数取决于机器，文中实测来自当前 10 个逻辑 CPU 的工作站。

不加 `--fast` 时关闭局部插值和较宽光深误差预算，保留保守模式的公式、容差与
求根停止条件。它仍包含第一轮的零散射区间排除与偏振延迟求值。重构后不承诺
与历史二进制逐位相同；对于敏感轨迹，细小浮点差异也会改变偏振演化。

`--threads N`（N>1）自动启用按光子 ID 派生的随机流。同一 seed 和 ID 的初始
随机状态固定，线程调度不会改变结果。使用一个线程做对照时加 `--photon-streams`。
新随机流与历史单一串行随机流不同，不应把相同 seed 的历史文件逐行当成匹配样本。
不加这两个选项时仍使用历史串行随机流。

更严格的快速设置：

```sh
build/fd11_fig7 --fast --tight --threads 8 --photons 100000 --seed 110703 \
  --output data/fd11_fast_tight_110703.txt
```

`--tight` 同时收紧绝热切换、逃逸及光深设置，不能把它仅理解为缓存精度开关。
所有影响结果的设置和随机流版本都写入输出头；线程数不改变输出内容。
旧绘图程序可以读取新文件，并会拒绝把不同数值设置的批次直接混合。

## 实现与适用范围

1. 在每个测地线区间构造四次局部插值，复用 `r, mu, x_e, twist, B1, B2, K`。
   用四个独立的交错检查点估计误差，不满足要求就细分，达到细分上限则恢复
   该小区间的实际磁场/几何求值。缓存不会跨测地线步或散射事件沿用。
   检查点误差估计不是数学上严格的全区间误差界，需用实际模型作收敛验证。
2. 从插值后的 `B1/B2` 重建偏振旋转轴，保持 `c²+s²=1`，不直接插值这两个归一化分量。
   Magnus 的端点误差控制、几何轨道精度和 Stokes 旋转结构保持原样。
3. 快速模式的光深 `atol/rtol` 为 `1e-6/1e-5`，缓存检查容差为 `1e-7`，
   散射点定位停止宽度为当前积分子区间长度的 `1e-7`。速度分布的边界仍参与
   分段，只去掉额外的内部速度分段点（`n_knots=2`）。
   共振判别式边界仍保留；QAGS 仍用于积分，没有改成无误差检查的固定步长求积。
4. `--fast --tight` 对应光深 `1e-8/1e-7`、缓存 `1e-9`、事件定位 `1e-9`，
   恢复 8 个速度分段点和 16 点扫描。
5. OpenMP 动态分配光子；每个 worker 拥有自己的输运器、RNG、GSL workspace 和缓存。
   GSL 错误处理器在主线程创建 worker 时设置。每批输出按 ID 排序，只有主线程写文件。
   worker 异常会传回主线程并使运行失败，不会静默漏掉光子或写出完成标记。

`--fast` 是有数值近似的模式。没有使用 `-ffast-math`、单精度或物理截断近似。
OpenMP 编译使用 GCC 的 `-fopenmp`，见
[GCC 官方文档](https://gcc.gnu.org/onlinedocs/gcc/OpenMP-and-OpenACC-Options.html)。

## 性能证据

插桩定位到 seed=110702 的第 4852 个光子：第一轮版本仅这个光子的光深积分
就耗时约 36 秒，调用被积函数约 1.93 亿次。该 seed 的 5,000 光子中，
光深积分占约 46.45 秒，Magnus 步进约 2.24 秒。插桩计时用于定位，
正式速度比较使用无插桩构建。

基线保存为 `build/performance_v2/original`：初始提交的数值头文件，加上共同的
按 ID 随机流和输出驱动，以便在完全相同的初始光子和随机序列下比较。
该驱动的历史串行模式与初始 `build/performance_audit/baseline` 在 1,000 光子上
输出逐字节一致。两种内核都以 GCC 16.2、`-O3 -DNDEBUG -fopenmp` 编译。

10,000 光子、seed=110701、相同的逐光子随机流，包含启动和输出的串行 A/B 墙钟计时：

| 内核/模式 | 线程 | 墙钟时间 | 相对原版单线程 |
| --- | ---: | ---: | ---: |
| 原始数值内核 | 1 | 45.33 s | 1× |
| 快速模式 | 1 | 8.36 s | 5.42× |
| 快速模式 | 8 | 2.31 s | 19.62× |

必须区分单核算法收益和多核收益。原版本身也可用多个进程并行，不能把
“原版单线程到快速八线程”的倍率说成相同核数的算法加速。
10 万光子、seed=110702 的同八线程对照：原始内核 138.25 s，快速模式
37.29 s，加速 3.71×。另外 10,000 光子、seed=110703、双方均使用 `--tight`
的同八线程对照为 37.65 s / 22.31 s，加速 1.69×。更严格设置会牺牲速度，
不同种子的慢光子比例也会影响加速比。

原始计时保存在 `build/performance_v2/speed.json`、`validation-times.json`
和 `final-times.json`；后者是最终源代码的快速模式计时。

## 精度验证

最终输出的比较保存在 `build/performance_v2/accuracy-final*.json`。
比较涵盖完整性/光子计数、能量/方向、散射次数、单光子 Stokes 范数，及
总计/未散射/散射三组的 `I,Q,U,V`。

| 对照 | 10,000 默认 | 100,000 默认 | 10,000 tight |
| --- | ---: | ---: | ---: |
| 逃逸光子数（两版相同） | 9,926 | 99,252 | 9,930 |
| 逃逸/吸收分类改变的光子 | 0 | 0 | 0 |
| 散射次数改变的逃逸光子 | 0 | 3 | 0 |
| 全局 I/能量/方向/Q/U/V 均值最大变化，相对参考标准误差 | 0.055σ | 0.022σ | 0.041σ |
| 检查箱中 I/Q/U 最大变化 | 0.068σ | 0.098σ | 0.142σ |
| 检查箱中 V 最大变化 | 0.240σ | 0.953σ | 0.222σ |

100,000 光子中，逐光子绝对差异的 95 分位数为：能量 `1.75e-7 keV`、
方向余弦 `5.27e-8`、Q/U/V 分别约 `1.01e-4 / 9.09e-5 / 1.25e-4`。
这些分位数不约束极少数离群轨迹：该样本的最大单光子 V 差异约 1.56。
V 最敏感的检查箱位于 10–40 keV、方向余弦 0–0.5，参考样本只有 300 个光子。

同一快速设置的一线程/八线程 10,000 光子输出逐字节一致；回归测试还检查了
2,053 光子跨输出批次的一线程/四线程一致性。缓存、回退、轨道界测试和原有
Python 分箱测试均通过。收紧数值设置不是每条敏感轨迹误差单调下降的保证。

分箱检查采用能量边界 `[0, .04, .4, 1, 2, 4, 10, 40, infinity]` 和四个等宽
方向余弦区间，报告参考样本中至少 100 个光子的箱。随机误差由逐光子权重的
样本二阶矩估计，吸收光子贡献为零。它用于量化数值变化，不是严格的误差上界，
也不是“未检出差异就证明无偏”的统计论证。

少数敏感轨迹的单光子 Q/U/V 差异可达到 O(1)，因此不能把快速模式用于需要
复现每个光子偏振轨迹的研究。对能谱和线偏振，可优先按最终实际分箱做集体验证；
高能尾部的圆偏振 V 更敏感，应增加样本并收紧设置再作收敛检查。
不要把 10 万样本的误差比例直接外推到数千万样本。

复现速度和误差比较（需要 NumPy）：

```sh
python3 py/benchmark_transport.py build/performance_v2/original build/fd11_fig7 \
  --fast --threads 8 --photons 10000 --seeds 110701
python3 py/compare_transport.py reference.txt fast.txt --output comparison.json
make test-transport-bounds test-transport-cache test-transport-driver
```

基线源文件快照、二进制和原始光子文件保存在本机 `build/performance_v2/`；
与其他 build 产物一样不纳入版本控制。测试覆盖缓存误差、细分与精确回退、
零通道/轨道界，以及跨输出批次的一线程/四线程逐字节一致性和光子计数。
